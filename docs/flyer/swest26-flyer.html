SWEST26 自由工作部門　作品紹介 — スマートホームプロトコルスタックの実装

simple_matter

スマートホーム標準「Matter」のプロトコルスタックを Rust でフルスクラッチ実装 — 公式実装の約 1/12 のメモリで動く、デバイスもコントローラも作れる自作スタック
Alexa / Google Home / Apple Home 等が採用するスマートホームの標準プロトコル Matter を仕様書から読み解き、市販エコシステムと相互運用できるところまで実装。
github.com/ciniml/simple_matter
Matter とは — 2019 年に Amazon・Apple・Google・Zigbee Alliance(現 CSA)が共同で立ち上げた Project CHIP を起源とするスマートホーム標準。メーカーを越えて同じデバイスを各社エコシステムから操作できる。2022 年 10 月に 1.0 公開、以後半年〜1 年周期で更新され最新は 1.6(2026 年 6 月)。本作は 1.3 相当を実装。
背景 — 既存実装の課題
公式実装(connectedhomeip)はフットプリントが巨大数百万行規模の C++ でビルドも重く、flash 1MB 超・RAM 数百 KB を要求。小型 MCU には載らず、読んで学ぶにも改造するにも大きすぎる。
Rust 実装(rs-matter)は実装の成熟度に課題公称でも flash 1MB / RAM 256KB。デバイス側中心でコントローラは作れず、機能面・相互運用実績も発展途上。
I/O 密結合でテストが実機頼み既存実装はソケット・無線と密結合しており、プロトコル処理単体の自動検証が難しい。開発の律速が実機デバッグになりがち。
102 KBコア flash 実測(RAM 24 KB)— rs-matter 公称下限の約 1/12
667 tests暗号化込みバイト列レベルの E2E を CI で常時実行
32 クラスタサーバクラスタ実装数(照明・錠・温調・センサ等 17 デバイス種)
3 トランスポートコミッショニング対応: UDP / BLE(BTP) / Thread

作ったもの

  • デバイス側とコントローラ側の両方を 1 つのコアで持つ Matter スタック
  • ESP32 に焼けば市販アプリ・chip-tool から操作できる照明・センサに
  • 自作 CLI smctl / ESP32 組込みコントローラから市販デバイスを操作
  • connectedhomeip では不可能な Windows 向け BLE 込みクロスビルドに対応

アーキテクチャ — sans-IO 設計

sans-IO = プロトコル処理を I/O から分離し「バイト列 → バイト列」の純粋な変換として書く設計手法。

発展形 — 汎用ファームウェア(再ビルド不要)

構成・GPIO 割当の設定変更/WASM スクリプト+OTA/ブラウザ書き込みツール

使用ハードウェア

ESP32-C6(NanoC6) ESP32-S3(AirQ) ESP32-H2(NanoH2 / Unit Gateway H2) ESP32-P4(Tab5) nRF52840 / RW612(未実装・移植予定)

主要機能

相互運用
公式 chip-tool と双方向で動作確認。attestation(DAC 証明書チェーン+CD 署名)は bypass 無しの実検証
デバイス側
コミッショニング(UDP/BLE/Thread)、購読・イベント・ACL・グループ受信、ICD(省電力)、工場出荷データ(mfg_tool 互換)
コントローラ
CLI smctl(pairing/read/write/subscribe/batch)と、ESP32 上で動く組込みコントローラ(BLE→WiFi 引き渡し、P4+H2 の Thread ハブ)
C++ 連携
既存 ESP-IDF C++17 資産から staticlib + C ヘッダで呼べるシム。デバイス/コントローラ × UDP/BLE/Thread 全組合せ実機確認済み
汎用 FW
1 つのバイナリで構成変更(OnOff→GPIO5 等を設定で差替)、WASM スクリプトの実行と OTA 更新(A/B スロット+ロールバック)
書込ツール
ブラウザだけで構成選択→個体情報生成(SPAKE2+ verifier)→書き込み→ペアリング用 QR/手動コード発行(サーバ不要)

こだわり・見どころ

  • 実機なしで暗号込み E2E テストsans-IO 設計により、コミッショニング全手順をワイヤ上のバイト列レベルで CI 検証。実機デバッグは「最後の一歩」だけに
  • フットプリント実測主義flash/RAM を CI で常時計測し閾値監視。コントローラ機能を足してもデバイス専用ビルドへの影響 ±128B 以内を機械検証
  • 規格の「正しさ」に投資デバイスに PIN を持たせない verifier 方式 PASE、実 PAA による証明書検証など、動くだけでなく仕様準拠に踏み込んだ
  • スタックから道具まで全部自作プロトコル・CLI・ESP32 移植・C FFI・WASM 実行系・Web 書き込みツールまで一気通貫で自作
